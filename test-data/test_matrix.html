hidden cases

Concurrency & resilience

hidden cases

Money systems get hit twice. A double-click, an overlapping scheduler tick, or a broker timeout must never place, exit, or size a position twice. Spec rule #3 mandates a 10s timeout, 3 retries and a fallback on every external call — that contract is currently asserted nowhere.

Flaws & coverage gaps

read before trusting the seeds

Found by diffing the engine code against the spec and the seed data. The first three are the ones that will actively mislead an auditor, because the seeds assert outcomes the code no longer produces.

F1 /confirm never recomputes gates Coverage

The confirm endpoint reads the stored gate_results JSONB and passes it straight through. The whole of GateValidator — every credit and debit gate — is exercised only by JUnit and by the live /recommend path. The offline S2 suite proves the confirm/reject state machine, not that any gate works.

Do: add a replay-backed /recommend test (the capture snapshot already exists under test-data/capture/snapshot/) so gate logic has one deterministic end-to-end path.

F2 Seed gate results describe rules the engine dropped Misleading

Debit seeds T-202 / T-208 / T-211 record a G1 of "breakeven PoP ≥ 35%". The current debit path computes something entirely different: G1D reward:risk ≥ 1.4, G2D breakeven ≤ 100 pts, G3D confidence ≥ MEDIUM, G4D debit ≤ 0.5% capital. Anyone auditing debit behaviour from the seeds is reading a spec the code abandoned.

Do: regenerate the debit seed gate_results from the live engine, or annotate them as "display-only, not engine output".

F3 Strategy matrix disagrees with spec and seeds Correctness

Neutral·Weak·Normal·Rich → code returns IRON_CONDOR, but spec and seed T-210 expect a Short Strangle. Neutral·Weak·High·Rich → code returns WIDE_IRON_CONDOR, seed T-204 says IRON_CONDOR. SHORT_STRADDLE/SHORT_STRANGLE are unreachable from StrategySelector. And weak-bullish skips while weak-bearish reroutes to neutral (IMPL_STATUS #19, still open) — an asymmetry with no stated rationale.

Do: decide whether strangles are in scope; if not, delete the dead enum branches and fix the two seed labels. Mirror the weak-bullish/bearish handling.

F4 G4 RoC divisor is DTE/7, spec says DTE/5 Spec drift

Spec §8 defines the DTE-adjusted RoC floor as 0.5% × (DTE/5); the code divides by 7 (calendar week). The threshold a trade must clear is materially different from the documented one. Pick one and make spec + code agree.

F5 T-210 passes G4 on lots it won't trade Sizing

The strangle's G4 was pre-set "passed" using a 6-lot RoC of 0.995%, but margin sizes the position to 3 lots where real RoC is 0.50% < the 0.70% floor. Because gates aren't recomputed after sizing (F1), the mismatch never surfaces. Combined with F3, the trade is unreachable anyway — but the pattern (gate green on numbers the position doesn't use) is worth banning.

F6 Two monitor mechanisms for one trade family Design

2-leg credit spreads decide on a live recomputed PoP ladder (stored T1/T2 Nifty levels are cosmetic); Iron Condors decide on stored bilateral Nifty levels. Same economic structure, two code paths — exactly the split that produced the "levels way too deep" Iron Condor you flagged. Consider unifying on PoP for both, or document loudly why they differ.

F7 Readjust test relies on non-physical inputs Test quality

T-401 forces actualNetPremiumPerUnit=1.00 and t3LossThreshold=9999999 to guarantee READJUST. It proves the chain fires, but not that MTM math is right on realistic premiums. Add a companion case with true entry premium and a real loss threshold.

F8 The entire /recommend pipeline has no offline path Coverage

Layers 1–5 (strategy, expected move, strike, gates, sizing) can only run against a live option chain. So concerns #2, #3 (override's effect on the recommendation), #4 (profile-driven sizing) and #6 (level computation) can't be verified without market hours. The capture snapshot exists but no S-script drives /recommend through it.

Do: wire a replay profile that serves snapshot/option_chain.json to /recommend — unlocks the largest block of amber rows above.

F9 External-deletion reconciliation is untested (concern #9) Coverage

PositionReconciliationService needs the live Upstox positions API and has no mock or seed to simulate "position closed out-of-band". There is no offline scenario for the exact case you asked about.

Do: inject a stub positions client returning an empty book for an ACTIVE trade; assert the trade is reconciled to closed + alert raised.

F10 Confidence=LOW silently blocks directional credit Behaviour

At Layer 1, a LOW-confidence directional credit strategy becomes NO_TRADE → fallback → REJECTED — before any gate runs. So S11 (data gaps) and S12 (commentary divergence), both LOW, are rejected upstream. That's defensible, but it isn't captured in any seed's expected outcome, so concern #1's "signal → recommendation" link looks broken when it's actually working as designed. Iron Condors are exempt (non-directional).

F11 A testing bypass can turn "SKIP" into a live trade Latent risk

When hardGateEnabled=false, GateValidator forces allHardGatesPassed=true even on real gate failures, and StrategySelector converts a SKIP/NO_TRADE decision into a fallback strategy marked PENDING_CONFIRM. That combination is fine in a test profile, but if the flag is ever true in a non-test environment the system will present tradeable cards for setups it is supposed to reject — including VIX-Extreme. Nothing asserts the flag is off in prod.

Do: add a startup assertion that hardGateEnabled=true whenever the active profile is not sandbox/test, and a test (PORT-06) that proves a real gate failure yields REJECTED in prod config.

F12 Position sizing is per-trade — no portfolio ceiling Risk

Layer 5 sizes each trade against full capital and its own margin. Two or three simultaneous ACTIVE trades can therefore each consume the 1.5% loss budget independently, so aggregate risk and total SPAN margin are unbounded by design. For a "consistency over returns" system this is the biggest structural gap — concentration and total-margin limits simply don't exist.

Do: add a portfolio guard that sums open risk/margin before sizing a new trade (PORT-02), and a cap on concurrent same-direction exposure.

F13 Silent volatility-regime downgrades change the strategy Observability

When historical vol or ATM IV is null, resolveIvRegime() silently returns FAIR, and ATM-IV lookup silently falls back to a VIX/100 proxy. Both quietly suppress every RICH-gated strategy (Iron Condor, credit spreads), so a data gap changes which trade you get with nothing written to data_gaps or shown to the user.

Do: record the IV source and any FAIR-by-fallback in data_gaps/score_breakdown so the downgrade is auditable (DQ-08).
