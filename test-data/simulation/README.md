# Simulation harness

Implements **Phase B** of `SIMULATION_PHASE_CONTRACT.md` (repo root). Drives Agent 3's
monitoring decision ladder through a hand-craftable market timeline, against a golden-fixture
ACTIVE trade.

```
simulation/
├── fixtures/golden/          ← the handoff artifact (contract §2). ONE per strategy.
│   ├── bull_put_10L.json
│   └── iron_condor_50L.json
├── scenarios/                ← Phase-B timelines you hand-edit ("play with the data")
│   ├── bull_put_walk.json
│   └── iron_condor_walk.json
├── sql/seed_golden_active.sql ← loads a golden fixture as an ACTIVE trade
├── capture_golden.sh         ← capture a REAL Phase-A trade → golden fixture (§5)
└── run_phase_b.sh            ← the conductor: walks a scenario, asserts each tick
```

The §5 **contract test** lives in `agent3-monitor` (`GoldenFixtureContractTest`), not this folder —
it validates every file under `fixtures/golden/` against the real `MonitorConfigDto` shape.

## Run it (Increment 0)

Prereq: Agent 3 running on `:8083`, and seeds `01_seed_user_profiles.sql` + `02_seed_agent1_signals.sql` loaded (the golden trades link to the 10L/50L profiles and signals S02/S05).

```bash
# 1. load the two golden trades as ACTIVE
psql "$DB_URL" -f test-data/simulation/sql/seed_golden_active.sql

# 2. walk a scenario
A3=http://localhost:8083 bash test-data/simulation/run_phase_b.sh \
   test-data/simulation/scenarios/bull_put_walk.json
```

The conductor prints expected vs actual action per tick and a pass/fail summary. **To
hand-craft**: edit `niftySpot` / `shortLegIv` / leg LTPs / `expectAction` in the scenario
JSON and re-run. The bull-put spots/IVs mirror the S3 calibration (DTE≈4) that is known to
produce HOLD→WATCH→READJUST→EXIT; if your Agent 3 derives DTE from `expiry − now` and your
run date drifts, nudge the spots or the fixture `expiryDate`.

## ⚠️ Golden fixtures are PROVISIONAL

These two files are **shape-correct bootstrap fixtures** derived from seeds T-301 / T-204 —
enough to build the harness. Per contract **§5**, before they are trusted they MUST be
**regenerated by capturing a real Phase-A run** (Agent1→2→5 entry). Until then, treat conductor
passes as "the decision ladder is wired correctly", not "the numbers are production-accurate".

**Capture real fixtures + lock the shape (§5 — now implemented):**

```bash
# after a real Agent1→2→5 entry has left an ACTIVE trade in the DB:
DB_URL='host=… dbname=… user=… sslmode=require' \
  ./capture_golden.sh <tradeId> fixtures/golden/bull_put_10L.json

# lock it — the contract test fails if any fixture drifts from MonitorConfigDto:
mvn -q -pl agent3-monitor test -Dtest=GoldenFixtureContractTest
```

`GoldenFixtureContractTest` reflects over `MonitorConfigDto`'s record components and fails if a
fixture is missing a field the engine now produces — the tripwire against stale fixtures (test-matrix
**F2**). It runs offline (no Spring / DB / Upstox) and checks every file in `fixtures/golden/`,
including leg completeness, Iron-Condor bilateral thresholds, `entry_fills` count, and a clean
serialize→deserialize round-trip.

## Increment 1 — built ✅

**Agent 3 — virtual clock + act seam** (`agent3-monitor`):
- `config/ClockConfig` — production `Clock` bean (`@Profile("!simulation")`, `Clock.system` in `agent3.clock.zone`, default `Asia/Kolkata`). Every `now()` at the DTE / market-hours / staleness / audit-timestamp sites is now `now(clock)`. Behaviour-identical in prod during market hours.
- `sim/` package (`@Profile("simulation")`): `SimClock` (a `java.time.Clock`), `SimClockService` (settable, backed by the V113 `sim_clock` singleton row), `SimClockConfig` (the sim `Clock` bean), `SimClockController`.
- `service/MonitorActionRouter` — the EXIT/READJUST/PAUSE routing, extracted from `MonitorSchedulerService` (single source; the scheduler delegates to it). `POST /evaluate/{id}?act=true` (gated to sandbox/simulation) routes the decision to Agent 5 **after** the evaluate transaction commits.

**Agent 5 — fault modes + P&L** (`agent5-execution`):
- `dto/SimFillMode` + the `X-Sim-Fill-Mode` header → `FILL | SLIPPAGE | PARTIAL_ROLLBACK | TIMEOUT_MARKET | MARGIN_REJECT`. Honored only when `simulate-fills`/`simulate-exit` is on. The simulate path is now fully offline (no Upstox margin call).
- `trade_pnl` written on every system-driven close (realised P&L = latest `monitoring_evaluations` MTM for the trade).

### Run the full offline loop

Start Agent 3 and Agent 5 with `-Dspring.profiles.active=sandbox,simulation` (sandbox → `simulate-fills=true` etc.; simulation → virtual clock + `act` allowed).

```bash
# 1. seed a golden ACTIVE trade
psql "$DB_URL" -f test-data/simulation/sql/seed_golden_active.sql

# 2. set virtual time
curl -s -XPOST localhost:8083/sim/clock/set -H 'Content-Type: application/json' \
     -d '{"at":"2026-07-14T10:00:00+05:30"}'

# 3. evaluate WITH act=true → decision routes to Agent 5 → CLOSE + trade_pnl
curl -s -XPOST "localhost:8083/api/v1/agent3/evaluate/b0000001-0000-0000-0000-000000000001?act=true" \
     -H 'Content-Type: application/json' \
     -d '{"niftySpot":23950,"vix":18,"shortLegLtp":210,"longLegLtp":130,"shortLegIv":0.21}'
#   → EXIT → Agent5 /exit (sandbox) → trade CLOSED, ledger TRADE_CLOSED, trade_pnl row

# optional: exercise an Agent 5 fault on a direct exit call
#   add header:  -H 'X-Sim-Fill-Mode: PARTIAL_ROLLBACK'   → EXIT_FAILED + critical alert
```

**Prod safety:** every sim bean is `@Profile("simulation")`; `act=true` requires sandbox/simulation; fault modes require `simulate-fills`; `SimClockService` logs a loud startup warning. (Ties to test-matrix F11 — a hard "fail if simulation active in prod" assertion is still TODO.)
